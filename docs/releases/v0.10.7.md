# Veltrix-Control v0.10.7 — Carbon console, 1:1

## Highlights

- **The delivered Carbon interface is now the product's console, unchanged.** The original
  `index.html`, `styles.css`, `app.js`, `shared.js`, icons, motion, and layout are
  served by the Controller at `/carbon/` and hosted in a WebView2 window opened from the
  native sidebar (**Console**). No redesign, no partial port: the kit renders exactly as
  delivered.
- **It is live, not a mockup.** A same-origin bridge replaces the kit's sample adapter with
  real data: the device table and metrics refresh from `/api/devices`, enrollment codes
  are created through `/api/enrollment/tokens`, Recent activity is built from
  `/api/audit`, and the workspace card, user, initials, build, and controller endpoint
  come from the signed-in session. The kit's own sample data remains only as the fallback
  when it is opened standalone without the bridge.
- **Native and console together:** the WPF Carbon shell (v0.10.6) remains for full
  administration; the Console window is the 1:1 kit surface. The launcher's browser
  fallback now opens `/carbon/` too.

## Limits (honest)

- The kit's secondary sections (Diagnostics, Managed files, Administration, Deployment,
  Operations, Integrations, Audit, Settings) still render their bundled sample content
  inside the console; only Overview, Devices, enrollment, and activity are live. The native
  WPF views remain the functional surfaces for those actions.
- The animated fleet topology and sparklines use the kit's own data, not platform history.

## Verification

- Release build with zero warnings: **PASS**; 156 tests pass.
- Controller publish serves `/carbon/index.html`, `assets/veltrix.js`, and
  `assets/styles.css` (HTTP 200) and the session cookie authenticates (verified against a
  disposable Controller instance).
