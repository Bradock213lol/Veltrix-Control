# Veltrix-Control v0.7.0 — Resource-aware compute scheduling

Veltrix-Control v0.7.0 turns authorized nodes into a managed compute pool with explicit
capacity, policy, and job lifecycle management.

## Highlights

- **Job queue** — queue bounded `.exe` jobs with CPU, memory, and disk requirements,
  priority, timeout, and retry limits.
- **Scheduler** — places jobs on online nodes that have capacity after reservations and
  currently running jobs. Placement considers priority order, node load, and per-node
  policy.
- **Workload policies** — Idle, Server, Compute, Gaming, and Maintenance modes with
  reserved CPU threads, memory, and disk. Gaming and Maintenance nodes never receive
  compute jobs.
- **Lifecycle** — queued, running, succeeded, failed, cancelled, and timed-out states with
  automatic retry, process-tree cancellation, bounded output, and complete audit history.
- **Honest capabilities** — GPU requirements are refused with a clear message because
  managed nodes do not yet report GPU capability; the platform never pretends hardware
  exists.

## Safety model

- Job creation and cancellation require `device.compute`; policy changes require
  `admin.manage`.
- Only absolute `.exe` paths can run; UNC paths, relative paths, and script files are
  rejected on both the Controller and the node.
- One compute job runs per node at a time, and it executes on a dedicated worker so other
  management operations and heartbeats continue.
- Timeouts and cancellations terminate the entire process tree.

## Verification

- Release build with zero warnings: **PASS**.
- Automated suites pass across unit, security, Agent, integration, and end-to-end tests,
  including scheduler placement, Gaming-mode blocking, GPU refusal, cancellation,
  validation, fixture execution, and timeout reporting.

## Known limitations

- The scheduler reserves capacity from policy and running jobs; it does not yet enforce
  quotas inside the operating system.
- GPU scheduling is intentionally not implemented until nodes report GPU capability.
- Binaries are not Authenticode-signed; Windows may show an unknown-publisher warning.
- Game-server adapters and integrations remain planned phases.
