# Veltrix-Control v0.6.0 — Backups, alerts, and automation

Veltrix-Control v0.6.0 protects selected data and reacts to fleet health conditions with
verified backups, deduplicated alerts, and operator-controlled automation rules.

## Highlights

- **Verified backups** — create zip archives of folders or files inside the managed root,
  verify their integrity, and restore only to a new destination. Every backup records its
  SHA-256, size, entry count, and completion state; a backup is never reported successful
  until the archive is written and hashed.
- **Retention** — completed backups older than their retention window are marked expired
  and a safe archive cleanup operation is queued, never deleting data silently.
- **Alerts** — the Controller continuously evaluates device offline, CPU, memory, and
  low-disk conditions. Open alerts are deduplicated, automatically resolved when the
  condition clears, acknowledgeable, and fully audited.
- **Automation** — rules with schedule, alert, device-online, and device-offline triggers,
  optional device-name conditions, cooldowns, recursion protection, and allow-listed
  actions. Rules may create alerts or queue restart, shutdown, or Windows Update scan
  operations. Every run is recorded with its outcome and detail.
- **Operations workspace** — a dedicated desktop surface for backups, alerts, and rules
  with run history.

## Safety model

- Backup and restore require `device.backup`; automation administration requires
  `admin.manage`.
- Restores always target a new, nonexistent destination; existing data is never overwritten.
- Automation actions are allow-listed and always run with explicit confirmation semantics,
  a cooldown, and full audit records. Automation-created alerts cannot retrigger alert rules.
- Archive extraction uses the same zip-slip, entry-count, and size protections as the file
  manager.

## Upgrade and compatibility

- One `Veltrix-Control-Setup.exe` still installs the Controller, Managed Node, or both.
- The database schema is extended automatically; existing state is preserved.
- All earlier workflows remain unchanged.

## Verification

- Release build with zero warnings: **PASS**.
- Automated suites pass across unit, security, Agent, integration, and end-to-end tests,
  including backup round trips, escape rejection, alert acknowledgement, automation
  lifecycle and validation, and viewer permission denial.

## Known limitations

- Backup archives are stored inside the managed root; store them on a separate volume for
  stronger protection.
- Alert evaluation runs on a 30-second cycle and reflects the latest heartbeat telemetry.
- Binaries are not Authenticode-signed; Windows may show an unknown-publisher warning.
- Compute scheduling, game-server adapters, and integrations remain planned phases.
