# Veltrix-Control v0.5.0 — Software and Windows Update lifecycle

Veltrix-Control v0.5.0 lets administrators deploy approved software and install Windows
updates across the fleet with visible progress, verification, and recoverable results.

## Highlights

- **Package registry** — register WinGet catalog packages, or MSI/EXE packages with an
  HTTPS URL and a SHA-256 checksum. Unverified downloads are never executed.
- **Deployments** — install, uninstall, or upgrade a package on one or many devices from a
  single confirmed action. Each device receives an individually tracked operation with its
  own state, error, and audit trail.
- **Progress and recovery** — per-device results, success/failure counts, deployment
  cancellation, restart-required handling, and bounded installer output.
- **Windows Update** — scan for available updates, review KB, severity, size, and download
  state, then install selected updates with reboot-required reporting. Administrator-only.
- **Background execution** — long installs and updates run on a dedicated agent worker, so
  heartbeats, telemetry, and other operations continue uninterrupted. Results that cannot
  be delivered immediately are stored and retried.

## Safety model

- Software operations require `device.software`; Windows Update requires `device.updates`.
- Operators cannot deploy software or install updates.
- Downloads must use HTTPS and match the registered SHA-256 checksum before execution.
- Every package registration, deployment, cancellation, scan, and installation is audited.

## Upgrade and compatibility

- One `Veltrix-Control-Setup.exe` still installs the Controller, Managed Node, or both.
- The database schema is extended automatically; existing state is preserved.
- Existing enrollment, telemetry, files, administration, and terminal workflows are
  unchanged.

## Verification

- Release build with zero warnings: **PASS**.
- Automated suites pass across unit, security, Agent, integration, and end-to-end tests,
  including deployment lifecycle, failure reporting, cancellation, validation, permission
  enforcement, and the complete Windows Update scan/install flow.

## Known limitations

- WinGet packages must be reachable from the managed node's service account; environments
  where the service account has no WinGet installation should publish MSI or EXE packages.
- Windows Update requires the Windows Update service to be available and uses the official
  Windows Update COM API.
- Binaries are not Authenticode-signed; Windows may show an unknown-publisher warning.
- Backups, automation, compute scheduling, game-server adapters, and integrations remain
  planned phases.
