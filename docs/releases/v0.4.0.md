# Veltrix-Control v0.4.0 — Controlled Windows administration

Veltrix-Control v0.4.0 lets authorized administrators perform routine Windows process,
service, power, and terminal work remotely with explicit policy and a complete audit trail.

## Highlights

- **Processes** — start an approved `.exe`, stop a process, and change priority. Process
  identity is re-verified before a mutation, and core Windows processes are protected.
- **Services** — start, stop, and change the startup type of Windows services. Critical
  services such as RPC, Defender, and the platform's own services cannot be stopped or
  disabled remotely.
- **Power** — scheduled restart and shutdown, logoff, sleep, and hibernation, all gated by
  a separate local node policy. Wake-on-LAN is available for nodes that report a MAC
  address.
- **Terminal** — audited PowerShell and CMD sessions with streaming output, command
  history through the audit log, cancellation, bounded buffers, idle cleanup, and multiple
  sessions per device.
- **Administration UI** — a dedicated workspace with processes, services, and terminal
  tabs, device selection, confirmations, and understandable errors.

## Safety model

- Four independent gates must pass: the Controller role permission, explicit user
  confirmation, the node's local policy switch, and the operation's argument validation.
- Protected process and service policies are enforced on the node, not just the UI.
- Every started session, command, service change, process change, power request, and wake
  attempt produces an audit event.

## Upgrade and compatibility

- One `Veltrix-Control-Setup.exe` still installs the Controller, Managed Node, or both.
- The database schema is extended automatically; existing state is preserved.
- Local administration policies default to disabled on nodes and are enabled by the
  installer for the Managed Node role.

## Verification

- Release build with zero warnings: **PASS**.
- Automated suites pass across unit, security, Agent, integration, and end-to-end tests,
  including protection-policy, local opt-in, terminal streaming, and wake tests.

## Known limitations

- Binaries are not Authenticode-signed; Windows may show an unknown-publisher warning.
- RealTime process priority may be refused by Windows unless the service account holds
  the required privilege.
- Wake-on-LAN requires the node to have reported a MAC address and the network to allow
  broadcast packets.
- Software deployment, Windows Update, backups, automation, compute scheduling, and
  game-server adapters remain planned phases.
